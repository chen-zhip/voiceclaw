# ADR-0010: Prototype-first dual change paths with Codex app-server

**Status:** Accepted

VoiceClaw will preserve ADR-0009 while splitting delivery into two dependency paths. The prototype critical path is Kernel Phase 0 → Desktop Host Contract → Harness Execution Routing → a Codex app-server Provider vertical slice → Desktop microphone-to-playback acceptance; Archive → Memory and other Feature Plugins form a deferred path rooted at the same Kernel. Archive and Memory remain official replaceable Feature Plugins, but neither blocks a non-persistent real-Harness prototype. Codex app-server is the first Provider because its explicit Thread, Turn, streamed Item, interruption, and terminal-status protocol exercises the Host, routing, and fencing contracts; an OpenAI-compatible endpoint, fake, no-op, or Relay-side adapter cannot satisfy that acceptance.

## Consequences

Kernel Phase 0 implements only the trusted local package, Contribution, Capability, grant, Secret broker, RPC, state graph, and fencing substrate required by the prototype. Routing is accepted against a deterministic provider-neutral `harness.execution@1` fixture so it can be completed before Codex. Only `integrate-codex-provider-prototype` owns acceptance against a real installed/authenticated app-server and the physical microphone-to-playback journey; fixture success cannot complete that Provider change. Archive and Memory retain all confirmed domain semantics and resume after the prototype foundation; `complete-harness-provider-integrations` becomes a later convergence change for additional Providers and advanced Provider features.

The prototype's implementation-neutral schemas and boundary types live in the internal `packages/contracts` workspace; importing those contracts does not create a runtime dependency on a provider package. Relay persists only Relay Control State through a Kernel-owned `ControlStateStore`, initially backed by a revisioned, serialized, atomically replaced JSON document. That store may contain grants, Host registration/revocation, Active Host Assignment generations, and content-free Conversation Thread Mappings, but never conversation messages, attachments, Semantic Output, Memory content, or evidence payloads. A minimal prototype Profile containing Kernel, Desktop Host, Routing, Codex, and STT/TTS must start and complete the real Harness path with no Archive or Memory package installed. Missing optional capabilities do not block activation; failures from an installed optional Archive or Memory provider degrade only that feature, remain visible, and do not change the Harness terminal outcome or trigger a storage/executor fallback.
