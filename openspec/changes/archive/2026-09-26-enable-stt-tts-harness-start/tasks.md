## TDD contract

Public seams: the adapter factory (`createAdapter` in `relay-server/src/adapters/index.ts`, exercised by `relay-server/test/adapters/factory-stt-tts.test.ts`), the bundled Relay environment builder (`buildRelayEnv` in `desktop/src/main/services/relay-server.ts`), the new Harness configuration module (`desktop/src/renderer/src/lib/stt-tts-harness-config.ts`), and the Settings read/write surface. Every RED step creates the named test and its stated assertion; a missing module or syntax error is not RED. Phase 1 is verifiable without any UI.

- [x] 1.6 Kernel invocation check rejects only stale generations. RED was reproduced by giving the existing kernel integration fixture a real Host id (`hostId: 'local-host-1'`): `expected … 'private_reasoning_forbidden' but got 'stale_generation'`. GREEN: the Kernel now validates only that the assignment exists and that its generation matches the envelope and payload. Verified with `yarn workspace relay-server vitest run test/integration/plugin-kernel-phase-zero.test.ts` and the full relay suite (567 passed / 36 skipped).

- [x] 1.7 Kernel shares the Relay's Control State store. `ControlStateStore.read()` returns an in-memory snapshot, and `PhaseZeroKernel.bootstrap` opened its own store, so the Kernel froze the assignment generation at bootstrap while the Relay's assignment service kept committing newer generations (`authoritativeReconnect` bumps on Host connect). Every dispatch then failed the Kernel's generation check with a bare `stale_generation` and never reached the instrumented gateway/Host-RPC/fence layers. `bootstrap` now accepts an existing store and `bootstrapProductionHostKernel` passes the Relay's instance, so one authority serves both. Verified with the full relay suite (567 passed / 36 skipped). Regression test for the injected-shared-store seam still owed.

- [x] 1.8 Kernel reaches the Desktop Host over its transport. The Kernel always dispatches through `startHostRpcInvocation`, whose transport callback was the in-process Contribution; production passed a stub, so every session died with `desktop_host_transport_required`. `bootstrap` now accepts a `hostTransport` port, `bootstrapProductionHostKernel` forwards it (and fails closed with an actionable message when absent), and `relay-server/src/index.ts` late-binds the Relay's `hostControl` into the Kernel. RED/GREEN at the new seam `relay-server/test/plugin-kernel/host-transport-bridge.test.ts`: the bridge must receive `{hostId, providerId}` from the assignment and its `{events}` result must be unwrapped into the Kernel's stream. Verified with the full relay suite.
